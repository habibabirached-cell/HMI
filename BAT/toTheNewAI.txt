1. PURPOSE — WHY WE ARE DOING THIS
================================================================================

This is a CEO demo setup with TWO machines:

  IDEUM (touch table)                    MAINGEAR (4×4K wall display)
  -------------------                    ---------------------------
  Static IP: 192.168.50.2                Static IP: 192.168.50.1
  Runs simplified touch UI (Ideum05)     Runs full DataCenter HMI + Vernova
  Sends HTTP commands to Maingear        Shows what the audience sees

When someone taps "Grid Connected" (or similar) on the Ideum touch table, the
Maingear wall must INSTANTLY switch from the DataCenterSmartPower HMI to the
Vernova Spark Engine dashboard. Reloading a single browser tab is too slow
(several seconds). 

SOLUTION: Preload BOTH apps in two separate fullscreen Chrome windows:
  - Vernova (http://localhost:5173) opens FIRST, spans all 4 displays, stays BEHIND
  - DCS (http://localhost:3003) opens SECOND, on top (what audience sees initially)
  - Switching = bring the other window to front (~milliseconds, like Alt+Tab)

Ideum will eventually trigger showVernova / showDcs via the existing cluster
link (HTTP POST Ideum → Maingear backend :5000 → WebSocket → browser). That
Ideum integration is NOT wired yet. Right now we are proving the Maingear side
works standalone with batch scripts.

See also: BAT/README.md, BAT/userManual.md, ideum.md (repo root).

4. STARTUP SEQUENCE (5 STEPS IN z_genesis.start.bat)
================================================================================

On each run, the script FIRST deletes old BAT\debug.txt and BAT\*.log files.

  Step 1/5  docker compose up -d
            → DCS UI :3003, backend :5000
            → via run-docker-compose.ps1 (tees output to console + logs)

  Step 2/5  Start Vernova npm run dev
            → minimized CMD window titled "Vernova dev"
            → via start-vernova-dev.bat
            → output in vernova-dev.log
            → 3 second pause before port checks

  Step 3/5  Wait for TCP ports 5000, 3003, 5173
            → via wait-for-ports.ps1 + Wait-ForTcpPort in kiosk-windows.ps1
            → prints progress every 15 seconds to console AND debug.txt
            → Vernova timeout: 300 seconds (5 min)

  Step 4/5  Open Vernova Chrome (behind, -NoActivate)
            → via open-vernova-chrome-4displays.bat
            → saves window handle as "Vernova" in kiosk-windows.json

  Step 5/5  Open DCS Chrome (foreground)
            → via repo-root open-chrome-window.ps1
            → saves window handle as "Dcs" in kiosk-windows.json

On success: CMD window closes (exit 0).
On failure: "Press any key to close..." so operator can read errors.

6. WHAT WENT WRONG (HISTORY OF FAILURES)
================================================================================

The operator ran z_genesis.start.bat multiple times. Docker and Vernova usually
work; Chrome never opened because step 3 or earlier steps crashed.

Failure A — Silent CMD, lots in debug.txt
  Output was written only to log files, not live to console. Fixed by tee
  helpers (_debug-log.bat, run-docker-compose.ps1, Write-WaitMsg).

Failure B — PowerShell inline command in bat (Start-Transcript ^|)
  CMD passed literal ^| to PowerShell instead of pipe. Fixed by moving port
  wait to wait-for-ports.ps1 (separate -File invocation).

Failure C — PowerShell 5.1 parse error: $($bucket)s in double-quoted strings
  Maingear runs PowerShell 5.1 (build 26100). Syntax like:
    "$($bucket)s elapsed"
  crashes at parse time with "Unexpected token 's'".
  FIXED (latest): use -f format strings:
    ('... {0}s elapsed ...' -f $Label, $bucket, $TimeoutSeconds)
  If you see this error again, search kiosk-windows.ps1 for "$(" followed by
  "s" immediately after closing paren in a double-quoted string — replace ALL
  with -f format strings or string concatenation.

Failure D — $script:GenesisTeeLogs wrong scope after dot-sourcing
  wait-for-ports.ps1 set $script:GenesisTeeLogs but Write-WaitMsg in
  kiosk-windows.ps1 read a different script scope → StrictMode crash.
  FIXED: use $global:GenesisTeeLogs.

Failure E — REPO_ROOT trailing backslash broke PowerShell args
  "C:\...\HMI\" escapes the closing quote in CMD → PowerShell prompts for
  EnvFile interactively.
  FIXED: _paths.bat sets REPO_ROOT without trailing backslash; paths use
  %REPO_ROOT%\subdir everywhere.

Failure F — _debug-log.bat mirror_run broke on npm.cmd / node.cmd
  Running npm without "call" in a batch subroutine loses return address.
  FIXED: call %* in mirror_run.

Failure G — debug.txt file lock
  Operator had debug.txt open in editor → "The process cannot access the file
  because it is being used by another process." Tell operator to close it.

Failure H — Port wait exits in <1 second
  Not a timeout — script parse/runtime error before polling. Check ports-wait.log
  and debug.txt "----- port wait -----" section for PowerShell errors.

Failure I — vernova-dev.log "not found" at error dump time
  Race: Vernova minimized window hadn't created the file yet. Added 3s timeout
  before port checks. Vernova typically ready in ~1 second once npm run dev runs.

CONFIRMED WORKING manually on Maingear:
  - docker compose up (containers start)
  - cd vernova-spark-engine_new && npm run dev (Vite on :5173, FastAPI on :8001)
  - Operator confirmed manual npm run dev works

10. WINDOWS / POWERSHELL GOTCHAS (DO NOT REINTRODUCE)
================================================================================

  1. PS 5.1 on Maingear — NOT PowerShell 7. Test all .ps1 under 5.1.
  2. Never use $($variable)s inside "double quotes" — use -f format strings.
  3. Never pass paths ending in \ inside quotes to PowerShell from CMD
     (e.g. BAD: -RepoRoot "C:\HMI\"  GOOD: -RepoRoot "C:\HMI")
  4. Never use inline powershell -Command with ^| pipe escapes in bat — use -File.
  5. Never run npm.cmd/node.cmd from batch subroutines without "call".
  6. goto inside if (...) blocks in batch — fragile; z_genesis uses labels.
  7. Start-Transcript on PS 5.1 may not show output on console — we use
     Write-WaitMsg / Write-TeeLine instead.
  8. kiosk-windows.ps1 line 197 had 3_000_000 — PS 5.1 rejects numeric separators
     (must be 3000000). Check if reintroduced.
  9. Do not commit: .env, kiosk-windows.json, node_modules
